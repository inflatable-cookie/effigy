# Logs

Evidence and decisions captured as the repo evolves. Logs are not a
chat transcript — they are the trail that lets a future reader (or
agent) reconstruct why a batch of work happened.

## Naming and segmentation

- One folder per month: `YYYY-MM/`
- One file per log entry: `DD-HHMMSS-<slug>.md`
- Slugs should describe the batch, not the agent or the ticket.

## Cadence

- Write a log when a meaningful batch of work lands — a feature ships,
  a decision is made, a planning pivot happens, or a pilot records
  evidence.
- Do not write a log for every micro-change. Use commits and the
  changelog for that.

## Meaningful batch evidence

A log entry should answer:

- What changed and why?
- What evidence backs the claim?
- What is the next move or the next unknown?
