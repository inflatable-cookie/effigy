Stage the development Linux artifact builder's source through the release profile's own supported host mount (effigy#715). A normal incremental `install:local` from a checkout the `effigy-release` profile does not share can now produce its matching Linux artifact automatically: the maintained `workspace:linux:artifact` task snapshots the checkout's tracked working tree (uncommitted edits included, Effigy state, secret files, ignored/untracked paths and submodule contents excluded by rule) into an owned `effigy-release`-profile child, stages the published Compose inputs beside it so the VM-hosted client can read them, binds that directory at `/workspace`, proves through the container that the bound bytes are the whole recorded closure (digest inventory plus source-file count), and copies only receipt-blessed artifact bytes, target and active version back into the checkout atomically. The checkout's project identity, caches and builder stay stable across incremental builds; changed source and deleted paths are refreshed in place; another checkout's staged source, an empty runtime-created directory, a missing or ambiguous profile mount, a symlink and an unreadable tracked path all refuse by name before compiling, while a link planted in the staged tree, or between the profile's mount and the owned child, is unlinked rather than followed out of it, and nothing outside the owned child is created or removed. A staged child that already holds entries without this checkout's own binding record is refused whole — nothing in it is written, cleaned, adopted or published — and the record is written before the first staged file lands as a `pending` record that proves ownership without claiming a closure, and the record becomes `complete` only once every file and its inventory were verified. Recovery never trusts the record for content: a staged file is rewritten whenever its bytes or its executable bit no longer carry the closure's entry, so a mode-only change in the caller is restaged rather than reused, and an interruption during an incremental refresh is completed by the next run instead of refusing forever. A caller or staged-tree edit during the build publishes nothing: the caller's current closure and the staged tree are re-proved against the compiled digest before any byte is copied back. The environment declares it with the new `workspace_source = "staged"` container option, which the private Linux builder sets; no VM, profile setting or mount is added or changed, and a release host still downloads.
