A managed host process no longer starts on a stale JavaScript install. When the manifest declares `[package_manager].js`, the preflight before any child or container starts compares each declared dependency's installed copy with the version the checkout's own lock resolves, for the package root at or above the process's working directory, and refuses a disagreement before the readiness budget is spent. The refusal names the dependency with its installed and resolved versions and the preparation that fixes it (the manager's frozen install, or `effigy bootstrap` when `[bootstrap].setup` is declared). Only readable locks and installed copies are compared: the binary Bun lock, pnpm and yarn locks, machine-linked packages and dependencies with no installed copy are left alone, so `effigy deps link` layouts and installs that live beside their container keep working. A listener that answers with the wrong status already ends the start as soon as it answers, so the stale front end's `500` is now reported instead of waiting out the readiness budget (effigy#954).
