**`--lock-wait-ms` now reaches nested Effigy runs and skill runs.** The flag is exported as `EFFIGY_LOCK_WAIT_MS` to the task's process environment, so a nested `effigy <selector>` that a step starts waits on the same lock instead of failing fast with exit 75. `effigy --lock-wait-ms <MS> skill run <skill>/<task>` is accepted, where it was rejected as an unknown argument. Other commands that take no task still refuse the flag, naming the supported forms.
