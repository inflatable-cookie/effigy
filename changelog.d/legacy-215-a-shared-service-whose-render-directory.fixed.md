A shared service whose render directory is gone is refused before anything changes. When a container whose own render is gone still exists, whichever render it was created from, `container up` names it and the recovery (remove that exact container with `rm -f`, then `effigy container up <NAME>`), and does not restore the render or stop, remove or start anything. Its named data volume is kept. A container whose render is present and differs is replaced as before, and a missing render with no container takes the normal creation path.
