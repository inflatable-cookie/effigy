The Linux native harness now deletes its own per-run Parallels snapshot after a successful run and reports an undecided disk-association inventory dispatch as transport-unavailable instead of a finding. Successful `qualification:linux:native-smoke` runs delete only their exact created `effigy-native-before-<id>` snapshot once guest outputs are cleaned up, verify its absence, and record the deletion in `native-smoke-complete.json`; failed runs keep the snapshot, and any snapshot referenced in `docs/qualification/**` or by code is never deleted. The disk-association inventory route shares the probes' bounded retry inside the occurrence window, and the helper's own exact refusal phase now propagates instead of masking every failed dispatch as `inventory-not-exited`. The reviewed `hdd0` compaction value moved from `on` to `off` with the 2026-11-11 SATA revert.
