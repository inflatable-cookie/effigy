**The built-in `minio` catalog service is retired.** Effigy no longer ships the MinIO fragment. A manifest whose `catalog = "minio"` would fall back to it - unqualified with no project, bundle or declared-source definition, or an explicit `baseline/minio` - fails with a refusal that names `silo`, and nothing is remapped. A `minio` fragment a consumer's own catalog source defines still resolves from that source, as Q-005 precedence requires. Silo keeps the same S3 API on `9000`, console on `9001`, `MINIO_ROOT_*` credentials (`minioadmin` defaults), persistent `/data` volume and `mc ready local` health check, so moving a service is a catalog-name change. Existing volumes and data are untouched; there is no migration. See [guide 085](docs/guides/085-v0.15.0-consumer-migration.md#service-catalog-packs-retired-sources-added).
