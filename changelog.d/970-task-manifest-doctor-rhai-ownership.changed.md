The task, manifest, doctor and Rhai surfaces now own their shared mechanisms once instead of once per caller. `effigy-tasks` keeps a refused request and a renderer refusal as different failure classes, so the runner reports a renderer failure as a UI failure instead of bad user input, and the catalog resolver callback carries a typed failure class, so a managed task reference falls back to a same-named builtin only when no catalog declares the task — an unreadable catalog graph now refuses instead of quietly running the builtin. The nearest-declaring-ancestor catalog rule has one owner, the legacy `source:target:options` system mount decodes once at load, the manifest schema's container and alias checks come from one value table, and the doctor's scan inventory reports invalid options and a budget stop through typed outcomes. The Vitest config scanner is its own module and says when a config could not be read instead of silently widening the run, and the Rhai `fs::` env-file readers answer from one projection and one dotenv key grammar (effigy#970).
