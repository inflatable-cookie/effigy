The task, manifest, doctor and Rhai surfaces now own their shared mechanisms once instead of once per caller. `effigy-tasks` keeps a refused request and a renderer refusal as different failure classes, so the runner reports a renderer failure as a UI failure instead of bad user input, and the catalog resolver callback carries a typed failure class: a managed task reference now falls back to a same-named builtin only when no catalog declares the task, so an unreadable catalog graph or an ambiguous selection refuses instead of quietly running the builtin. The nearest-declaring-ancestor catalog rule has one owner, the legacy `source:target:options` system mount decodes once at load, the manifest schema's container and alias checks come from one value table, and the doctor's scan inventory reports invalid options and a budget stop through typed outcomes. The Vitest config scanner is its own module, reports a config it cannot read instead of silently widening the run, and now decodes string literals as text, so a non-ASCII `test.dir` such as `tést` reaches `--dir` intact. The Rhai `fs::` surface registers its functions from one table and answers every env-file read from one projection and one dotenv key grammar, and a recursive listing refuses a missing or non-directory root instead of reporting an empty directory (effigy#970).
