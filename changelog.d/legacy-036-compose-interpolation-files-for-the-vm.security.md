Compose interpolation files for the VM-hosted Colima backend are per invocation: a fresh random name, `O_EXCL|O_NOFOLLOW`, mode 0600 inside a verified 0700 `$EFFIGY_HOME/compose-env/` directory, removed when the Compose child is reaped. The v0.15 development line reused content-named `$EFFIGY_HOME/compose-env/<digest>.env` files that carried explicit environment values, possibly secrets, and never pruned them; that exposure was introduced and fixed in this development line. Legacy `<16 hex>.env` files are not removed automatically: they carry no lock, so no invocation can prove they are idle. The first invocation reports how many it left. Development builds may have left such artifacts. Once no pre-fix build is running, delete `$EFFIGY_HOME/compose-env/<16 hex>.env` by hand. A crash leaves its `compose-` file in place: no invocation removes it automatically, and the next invocation reports how many such files remain. A free file lock does not prove the Compose group closed, so the sweep no longer removes them. Removing a `compose-` file by hand is safe once no Effigy process is running. Interpolation file removal refuses an occupied quarantine name and never replaces it, so a removal no longer clobbers a file. This does not mean no durable secret copies exist.
