Human errors from `effigy` now lead with a short plain-English headline, an optional one-line explanation and a clear `Next:` action, with machine-oriented context — manifest paths, catalog lists and backend diagnostics — in a separated `Details:` block underneath instead of glued onto one long run-on line. `effigy_ui::HumanError` gained `explain`/`detail` builders and `render_warning_text()`; existing errors that set neither keep their exact earlier text and `--json` shape, and `error.human` only gains a `details` array when one is present. The day-to-day `RunnerError` variants (manifest read/parse/compose, task routing, container surface and runtime policy, the environment capability refusal, and the gateway variants) are mapped onto it, so they no longer fall back to a raw `Display` chain (effigy#1090).
