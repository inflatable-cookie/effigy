`effigy container shell` reports one completion step on every route. Inside a workspace container the handoff-local shell finished cell reported a hand-written `[ok] finished container shell for …` literal that ignored the colour decision every other step takes; it now renders through the same `effigy_runtime::shell::container_shell_completion` owner as the interactive and command-mode host routes, so the line is styled (and suppressed under `NO_COLOR`) exactly as elsewhere, and a failing handoff command still refuses with its status. The environment facade behind `container up/down/reset/shell` now keeps the class of a failed container inventory read — an engine that answered it is not running or a runtime that cannot launch is reported as unavailable tooling, a refused observation as unparsable evidence, and only a plain failed command as an inconsistent observation — instead of flattening every case into one text, and it no longer panics when its fixed evidence cannot be built (effigy#983).
