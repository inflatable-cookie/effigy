A foreground memory sentinel whose owner is SIGKILLed no longer parks forever when the run's process group is empty. After owner-loss it inventories the recorded groups with the same membership rows the sentinel uses (including Darwin `getpgid` ESRCH skips so a stale `proc_listpgrppids` pid is not Unproven residue) and, once those groups and the cleanup pin are closed, settles `interrupted` and drops the checkout gates (`supervise/memory.rs` `wait_for_closure` / `park_unproved`). An unproved closure still parks, then re-checks every 250 ms.
