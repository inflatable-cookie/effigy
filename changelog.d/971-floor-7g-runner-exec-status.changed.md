Container exec argv, task status and managed wait observations now have one owner each. Compose-exec argv building and parsing moved out of the exec transport into `exec_command::transport::argv`, and the bounded capture API moved into `exec_command::bounded`, so the transport keeps only its plans. `execute/api.rs` keeps request assembly and hands runtime-target resolution to a new `execute::runtime_inputs` module, and the runner's duplicate `ExecutionBindingKind` is gone in favour of the shared `effigy_execution` enum. `effigy tasks status` reports one typed `TaskState` (JSON and text unchanged) and fails instead of printing a shortened status when a render fails. A managed wait observation that cannot be recorded, and a receipt that cannot be settled, are now reported to the run owner rather than discarded, and an unobserved host graph reads as absent instead of as a complete empty one. The container cargo-input refresh now includes untracked Cargo inputs and carries path names as their own bytes, failing closed on a platform that cannot represent them, and both preparation commands now hand the plan builder a `compose exec` tail, so the plan they run carries the Compose prefix once. The unused `support/workspace_private.rs` refusal scaffold is retired and the managed `scheduler` shim is folded into run-spec sequence rendering.
