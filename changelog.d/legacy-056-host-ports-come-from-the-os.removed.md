**Breaking:** **Host ports come from the OS or Compose.** A generated service publishes `127.0.0.1::<container-port>` and `up` reads the assigned port back into its route, so nothing is reserved between runs and a recreate or a VM restart can move a port. A database client, bookmark, `.env` value or editor connection that hardcodes a generated port breaks. Pin it in `[containers.<NAME>.host].ports`, or opt into `[containers.<NAME>.host].stable_ports = true`, which derives one host port per published container port from the checkout path and never records or probes it. A pin is used as written and a collision now fails naming the process that holds it. The 100-port project ranges, the port registry and `effigy container ports status|reclaim` are gone.
