The one-release compatibility translations are gone. `compose_file` is refused by ordinary commands with an error naming `effigy container migrate <name>`, which remains the converter and still proves the render is unchanged; retired `[bootstrap]` spellings (`run`, inline `setup`/`start` definitions and chains, the `submodules` policy string, `children`), the manual `[manifest].include` `optional`/`override` flags and the kebab-case `[contracts].schema-index`, `[contracts].selection-contract` and `[sources.<name>].rev-file` keys are manifest errors that name their replacement, and the v0.14 `.effigy/runtime/compose/.effigy-runtime.json` backend file is no longer read (name the engine with `EFFIGY_COMPOSE_BACKEND`). The one-release notices for retired `~/.effigy/catalog-packs/` and `~/.effigy/catalog/` state and for the retired baseline `minio` service are removed too: existing directories, volumes and data stay untouched, and an unresolvable service is the ordinary not-found. A direct upgrade from v0.14.1 goes through the explicit migration steps in guide 085.
