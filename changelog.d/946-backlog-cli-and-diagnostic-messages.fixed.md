Six diagnostics from the lead and papercut backlog now say what actually happened. Machine-local `[bundle.<name>].inputs` values are judged against the effective bundle rather than a pinned snapshot that the next `dev` or `container up` replaces, so a stale pin no longer warns that the bundle "does not declare that input" when the refreshed one does. An operator or private directory refusal names the mode rule it broke — `Trust::Operator` refuses a group or other write bit while accepting a group-readable 0755, and `Trust::Private` refuses any group or other bit — instead of calling both "readable by other users", and one helper renders that sentence for the store, gate and state-root paths so the wording and the `chmod 700` remedy cannot drift. A failed command whose `--json` payload is a whole envelope now carries the nested `error.human.what_failed`, evidence and `next_action` into the outer form, instead of "command failed (json output available)" with a null action. A retained failed-step record under a scratch root that is itself named `effigy` stays at `<root>/effigy/failed-steps/<run id>/` — the doubled segment is the namespace a later sweep descends into, and the guide now says so. `effigy test:focused` exports `EFFIGY_EXECUTABLE` as this checkout's `target/debug/effigy`, building it once through the Oxide selector route when it is missing, so a focused integration or lib test that nests an Effigy invocation no longer fails late as a relative custody executable. The feedback source scan requires the opening brace of a `\u{...}` escape, so a brace-less `'\uAB}'` is left visible as malformed code rather than blanked as a literal, and its docstring now claims only the notation it checks instead of rustc's whole grammar (effigy#946).
