`EFFIGY_STRICT_PERSISTENCE=1` opts a process into a run that prepares nothing: no store creation, schema `ALTER`/backfill, expired-row prune or checkpoint (at `COMMIT` or at the last connection's close), so a plain foreground admitted task's persistence is exactly its terminal row plus that row's log and wal-index frames. A journal that is not already prepared is refused **before the admission hook runs**, with a typed refusal naming `effigy run prepare` — the new step that prepares a checkout journal outside a strict run, with `--check` to verify that nothing would be written. Contract 049 now states the complete strict contribution with its arithmetic: `32 + 16 × (page size + 24)` bytes of write-ahead log, 0 bytes of main database, one 32 KiB wal-index block, and the one premise left (a wal-index that did not exist yet is sized by the frames other writers left in the shared log). Behaviour without the switch is unchanged (effigy#981).
