`EFFIGY_STRICT_PERSISTENCE=1` opts a process into a run that prepares nothing: no store creation, schema `ALTER`/backfill, expired-row prune or checkpoint (at `COMMIT` or at the last connection's close), and no maintenance either — checkpoint, vacuum, retention pass, machine compaction and the explicit repair all refuse or do nothing under the switch, and even observing the write-ahead log no longer checkpoints it. A journal that is not already prepared, or that needs recovery (a rollback journal, a torn log, or a log whose wal-index is missing), is refused **before the admission hook runs**, with a typed refusal naming `effigy run prepare` — the new step that prepares a checkout journal outside a strict run, with `--check` to verify that nothing would be written. Contract 049 now states the strict route's complete physical contribution with file:line: 0 bytes of main database, one 32 KiB wal-index page, one row of at most 960 stored bytes, and a write-ahead log of `32 + 21 × (page size + 24)` = 86,552 bytes as a per-run verified budget, under a premise-free ceiling of one frame per store page. The budget is measured by the tests (3 frames in every state) and each strict run checks its own appended frames against it, reporting a run that exceeds it rather than passing inside a claim it did not meet. Behaviour without the switch is unchanged (effigy#981).
