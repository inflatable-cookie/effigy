A workspace container running the legacy production context now behaves the way Effigy behaves on the host: it reads the checkout's `effigy.toml` with its includes and bundles, resolves tasks, built-ins, exec aliases and every deferral form normally, and runs them in the container it is already inside. The earlier pinned-manifest task classification, the in-container task allowlist and the long host-authority refusal are gone; the only refusal left is the one thing the container cannot do, a task explicitly declared `run_in = "host"`, which now fails in one line naming the host checkout. This restores `effigy prep` in deferring legacy sites (effigy#1044) and the ordinary declared tasks that the removed allowlist refused (effigy#1015). The qualified v2 guest, which holds an admitted session and a host channel, is unchanged.
