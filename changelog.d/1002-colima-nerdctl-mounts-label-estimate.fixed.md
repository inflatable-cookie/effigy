The Colima nerdctl compose fallback now estimates the `nerdctl/mounts` label from the row shape nerdctl 2.3.1 actually serializes. Volume rows carry `Type`, `Name`, `Source`, `Destination`, `Driver`, `Mode`, `RW` and `Propagation`, their source is the containerd volume-store data path under an eight-hex socket digest, and the platform name is the top-level `name:` alias, the `data_from` owner's name, or Compose's `{project}_{key}` default. `tmpfs` rows carry the literal `tmpfs` source and the `noexec,nosuid,nodev` mode. The previous model counted every volume as a bind of a project-prefixed name below a 64-byte hash segment, which overstated volume rows by a prefix and understated them by the name and driver fields; a recorded two-row label from a running 2.3.1 container now matches the estimate byte for byte. The refusal states containerd's real limit separately: one label whose key plus value exceeds 4096 bytes fails at container create on nerdctl before 2.3.2, while the conservative 3900-byte preflight budget is Effigy's own headroom. A refused set also reports how many bind, volume and tmpfs rows it holds, so an over-limit environment knows which kind of mount to reduce.
