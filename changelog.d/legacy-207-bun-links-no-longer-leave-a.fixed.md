Bun links no longer leave a machine-wide registration behind. `deps link bun` retires the registration it created once the consumer symlink and ledger exist, and an interrupt retires the same registrations before the signal stops the command. Retiral is the exact `(consumer root, library)` claim, so a sibling Bun root in the same checkout keeps its own claim. The completion retiral runs inside the apply's own index transaction after the ledger commits: a failed ledger write leaves the claim, registration and ledger untouched, a failed index commit restores any registration it retired and rolls the ledger and consumer links back, and a re-link over an existing claim always writes the retired claim out. An interrupted owner retires only what its own apply started. The transaction marks the moment it becomes able to create a registration, so a link that merely wanted the index lock retires nothing; the watcher then takes the index lock itself with a bounded wait and retains any registration another consumer claims, or one it cannot verify. It stops the whole `bun` process tree first — handler installed before the owner can create anything, spawns reserved and published, children in their own process group — and the command waits for the pending cleanup before returning. A shared or foreign registration is never removed. This is what stopped registrations pointing at deleted worktrees accumulating.
