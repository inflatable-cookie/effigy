**A container-mode workspace is prepared for the workspace client.** Host Prepare publishes an immutable guest context and a version-locked Linux Effigy into the container, outside the bind-mounted checkout. Activation publishes it — `effigy container up`, a task's environment apply and the workspace handoff all go through the same Prepare — so the recovery command the entry refusals name really does repair the state. The context carries: `/run/effigy/context/<generation>/context.json` with the exact host and guest versions, the executable digest, the protocol, and the checkout, environment, container and VM-boot generations it belongs to; `/run/effigy/bin/<digest>/effigy` in a guest-private store that new invocations reach through `/usr/local/bin/effigy`; and, when the session supplies one, a 0600 enrolment credential. The artifact family is the image's platform **and** C library — a glibc image takes the `*-gnu` artifact and a musl image the `*-musl` one — and an image whose libc the host cannot prove, or that has no artifact for its family, refuses Prepare instead of running bytes built against another C library. The digest is verified, not declared: the artifact must carry a producer receipt naming its target and SHA-256, a release download must match the checksum the release publishes beside it, and the executable the guest will run is re-hashed in the container. A guest authenticates it with one digest probe, so a multi-megabyte executable never lands in a bounded command's stdout budget. A published generation and an installed executable are never rewritten, so a run that started on one keeps its exact bytes. Hybrid mode publishes none of this. The context document is `effigy.workspace-context.v1` (contract 052 §8.2, §8.9, §8.11).
