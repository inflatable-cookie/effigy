**`test:focused` locks per invocation, not per task.** Its gate is keyed by the arguments its command receives as well as the resolved task, so two different test filters run at the same time and two identical invocations still exclude one another. The second identical invocation waits about two minutes by default; `--lock-wait-ms` or `EFFIGY_LOCK_WAIT_MS`, `0` included, replaces that default. An invocation with no task arguments keeps the plain `task:test:focused` gate, and every other task keeps one gate per declared task (Q-015).
