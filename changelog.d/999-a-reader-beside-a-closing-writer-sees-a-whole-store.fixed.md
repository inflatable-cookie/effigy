A reader of `kernel.db` or `machine.db` can no longer see a torn store when a writer checkpoints beside it. The read of a checkpointed store used an immutable SQLite open, which takes no lock and sees no checkpoint: a writer that opened beside it and carried its log into the database mid-read left the reader a mixture of the old and the new page trees, reported as `database disk image is malformed` for a store that was never damaged (and, in a tighter race, as a committed row that read as absent). A checkpointed store on a writable root is now read through SQLite's own write-ahead log with one query-only connection, which sees committed records and a consistent checkpoint image while a writer beside it is no obstacle; it materialises the write-ahead index for the length of the read only, writes no database page of its own, leaves no file behind and changes no database byte. A read-only or copied checkout has no writer to race and keeps the immutable open, which needs no lock, no index and no file (effigy#999).
