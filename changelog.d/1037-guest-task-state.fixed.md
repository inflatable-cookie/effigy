An ordinary container-routed task run from an `effigy workspace` handoff (for example `effigy sync:db`) no longer stops before its wrapped command with `open <checkout>/.effigy/state: Permission denied`. A guest keeps its own task journal, gates and custody beside the container's HOME (`<HOME>/.effigy/guest-checkouts/<checkout-digest>/.effigy/state`, private to the workspace user), keyed by the mounted checkout, so admission, execution, output and exit status are preserved while the read-only host-state mask is never opened, adopted or repaired. Host-routed tasks keep `<checkout>/.effigy/state` and their existing ownership and error handling, and a guest with no absolute HOME refuses naming the missing fact rather than falling back to host state.
