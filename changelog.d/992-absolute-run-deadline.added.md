A new opt-in `EFFIGY_RUN_DEADLINE_MS` gives one invocation a single absolute deadline, sampled once at process start on the monotonic clock. Admission (including a hung hook, a late grant and stalled v2 report acknowledgements), the workload and Effigy's own settlement all draw on the same ceiling, with a stated 10-second settlement allowance; a deadline that cannot fit the allowance refuses before anything starts, admission expiry refuses with a typed `deadline` decision before the workload spawns, and any settlement that is not positively complete is reported as an interrupted run with residue, named retained resources, no completeness footer and exit 124 — never success. Nested Effigy children receive only the remaining workload budget, so they cannot extend the parent's deadline. The run's evidence line and the task JSON record the clock, an observable origin and the remaining time observed in each phase. The feature is off by default and changes nothing when unset.
