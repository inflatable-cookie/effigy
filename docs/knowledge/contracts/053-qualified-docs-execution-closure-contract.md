## Exact closure

The first supported closure is the three ordered host docs leaves selected by
`qa:docs`: links, the declared paths list, then the named
`northstar/retired-concepts` task. Existing ordering, outputs, failure propagation
and checker semantics must remain. The outer selector's label is insufficient;
the effective selected manifests, includes and task definitions are inputs.

The known retired recipe is `bun run {skill}/scripts/retired-concepts.ts {args}`.
Its script reads the retired manifest and uses Git `rev-parse`, `ls-files` and
`grep` with literal argument arrays. An arbitrary script, altered recipe,
additional passthrough, shell hook, task wrapper or unknown nested tool is not
implicitly supported. Nucleus must not reproduce Effigy resolution or replace
the checker with a similar implementation.

Literal caller argv and “no caller-controlled shell hooks” do not forbid every
internal shell. A reviewed fixed internal shell is permitted only with its
exact executable and fixed command bytes declared and enforced. A PATH-resolved
`sh -c` over mutable manifest text is not that proof. Prefer the existing Docs
builtin dispatcher and literal execution of the exact retired recipe; do not
build a general shellless task engine or alter ordinary task defaults.

ownership and bounded lifetime, plus the explicitly accepted host/runtime

execution bindings without claiming infrastructure provenance it accepts by
