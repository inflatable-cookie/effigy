# 013 Cross-Repo Vision Adoption Playbook v1

Status: Draft
Owner: Platform Lead + Repo Maintainers
Purpose: provide a repeatable approach for rolling Effigy vision standards across multiple repositories.

## 1. Adoption Objectives

1. Align repository behavior and docs with the same core vision constraints.
2. Minimize bespoke process differences that increase operational variance.
3. Make maturity movement trackable across repositories (`007`, `010`).

## 2. Rollout Phases

### Phase 1: Baseline Discovery

1. Capture current workflows, contract usage, and release gate behavior.
2. Identify top drift points against vision tags.
3. Produce initial maturity scorecard snapshot (`010`).

### Phase 2: Core Alignment

1. Align key command behavior and contract docs to canonical expectations.
2. Add minimal governance checkpoints and exception handling (`005`, `006`).
3. Standardize critical guide language using canon (`012`).

### Phase 3: Operational Hardening

1. Establish routine governance reviews (`009`) and metric tracking (`003`).
2. Reduce repeated exceptions by fixing structural causes.
3. Confirm release/log artifacts consistently include vision deltas.

### Phase 4: Continuous Improvement

1. Promote successful patterns into shared playbooks and templates.
2. Reassess maturity quarterly and adjust repo-specific priorities.
3. Retire legacy process variants with no strategic value.

## 3. Minimum Adoption Kit

Each repository should adopt at minimum:

1. Vision index link and core artifact references.
2. Exception policy usage and owner model.
3. Governance review cadence with named owners.
4. Maturity scorecard with evidence-backed staging.
5. Release/log language that includes vision target deltas.

## 4. Escalation Signals

1. Repeated contract drift across release windows.
2. Persistent exceptions with no closure movement.
3. Stage stagnation for two or more quarterly reviews.
4. Frequent ambiguity/failure issues without remediation quality.

## 5. Success Signals

1. Repositories move at least one maturity stage over planned windows.
2. Cross-repo terminology and tag usage remain consistent.
3. Exception volume trends down while gate reliability trends up.
4. Governance actions close within expected timelines.

## Next Task

Create a cross-repo rollout scorecard template that compares maturity, risk posture, and exception burden across repositories.
