# 085 - v0.15.0 Consumer Migration

This checklist is for consumers moving from v0.14.1 to v0.15.0. Most projects
need no manifest change. Check the rows below that match what your project
uses. The [release contract](../knowledge/contracts/release.md)
owns release authorization; the linked contracts own the behavior described here.

## Service catalog: packs retired, sources added

The catalog-pack runtime is retired. `effigy service pack` commands now refuse
with the replacement, and the workspace no longer receives a pack from the
host. Installed pack state in `~/.effigy/catalog-packs/` (host or guest) is
ignored with a notice and left untouched; delete it when convenient.

Pack v1.2.0 is byte-identical to the 0.15.0 compiled baseline, and earlier
packs carried the same service assets except `silo`, which v1.2.0 added, so
projects resolve the same services with no change. To add or change services without an Effigy release, use a
catalog source: the project's `infra/dev/catalog/`, a bundle's `catalog/`, or
a declared `[catalog.sources.<name>]` pinned by `effigy bundle sync`. See
[guide 067](067-catalog-services-reference.md#catalog-sources).

Remove `release.sync-catalog-pack-support-policy` from `[release]` if present;
it is now a manifest error.

## Removed surfaces

- Replace `effigy watch` with your tool's native watch option or explicit task runs.
- Replace `effigy tasks migrate` with explicit task and test-suite definitions;
  inspect `effigy config` for examples.
- Unset `EFFIGY_MANAGED_STREAM` and use `--headless`. A set variable now errors
  before managed children launch, including with `--headless` already present.
- Remove `[manifest].root`; it now reports a source-specific error.
- Move fragments from `~/.effigy/catalog/` to each repository's
  `infra/dev/catalog/`. The old directory is ignored with a warning and preserved.
- `effigy gateway recover` is retired. v0.14.1 identity-bearing gateway upgrades
  retain `gateway up`/`down`. Pre-0.14 numeric-only state requires administrator
  migration as described in [architecture 034](../knowledge/architecture/034-gateway-legacy-upgrade-recovery.md).
- Run docs QA selectors directly instead of `docs qualified`. The private
  assurance recipe and build profile are removed.
- Listener transition receipts are no longer read or written; existing files
  stay untouched. Current listener state and diagnostics remain available.
- `[drafts]`, `draft` step keys, QA member `surface = "draft"`, `effigy draft`
  and `effigy drafts` are removed. Move each definition to
  `[tasks.<name>]` with `visibility = "internal"`, replace `draft` steps with
  `task = "<name>"`, and run the task by name. The manifest error names the
  replacement; see [contract 046](../knowledge/contracts/046-published-and-draft-task-surface-contract.md).
- `[shell]` is removed. Managed shell tabs always run
  `exec ${SHELL:-/bin/zsh} -i`; delete the table.
- `effigy gateway setup-listener-handoff`, `listener-handoff-status` and
  `remove-listener-handoff` are retired with the experimental listener handoff.
  There is no replacement: the gateway runs as your user, so use
  `effigy gateway up` and inspect it with `effigy gateway status`.
- Delete `[demos]` from every manifest and drop `effigy demo` from scripts and
  CI. The demo feature is gone with no replacement: the registry, receipts,
  retained history and browser no longer exist, and the `demo.*` Rhai host
  features are gone too. Record terminal sessions with an external tool.
  `effigy demo` and a `[demos]` table both fail with that explanation, and
  `effigy config --target demos` no longer exists.
- `effigy contracts validate-selection` is folded into `check-json`. Use
  `effigy contracts check-json --validate-selection` for this run's payload
  (already implied by `--print-selected=json`), or
  `effigy contracts check-json --validate-selection --artifact <PATH>` for a
  stored artifact. The command refuses with this replacement.
- `effigy contracts check-json` no longer assumes Effigy's documentation paths.
  Declare your own under `[contracts]` in `effigy.toml`:

  ```toml
  [contracts]
  schema_index = "docs/knowledge/contracts/json-schema-index.json"
  selection_contract = "docs/knowledge/contracts/json-selection-contract.json"
  ```

  A project that declares neither is refused with `no JSON schema index
  configured`. `--index` and `--contract` still override the configured paths.
  If you validate command payloads beyond schema/schema_version identity, add a
  `payload_schemas` map to your index (schema id → Draft 2020-12 document,
  relative to the index file); see
  [contract 054](../knowledge/contracts/054-project-json-contract-validation-contract.md).

Delete `identity`, `unlock` and `external` declarations under `[secrets.vault]`.
They are retired after consumer cleanup; the error names the file and line.
These keys only restated the passphrase default. Vault paths, stored values
and runtime unlocks keep their existing behavior.

## Behavior changes

| If you rely on… | What changes |
| --- | --- |
| `deploy apply` or `deploy redeploy` | Both refuse as not yet supported, including with `--yes`, and name the unexecuted obligations. Model/export and environment configuration stay compatible; old reports remain readable. Use model/export while full execution is designed in the deploy lane. See [guide 074](074-deployment-guide.md). |
| Detached stacks (`startup = "detached"`, e.g. the DecodeLabs bundle) | Before `effigy container up --detach` reactivates a running stack, every container in the Compose project that the up can start or recreate must be proven owned by this checkout, running or stopped. Stopped declared siblings must carry this checkout's checkout and scope labels; an unlabelled stopped container is not proven and Effigy refuses. The pre-label bind-mount exception in the next row applies only to running containers with verified identity in an unscoped checkout. Editing the manifest of a running stack and running `up --detach` applies the change. A *partial* activation (one that failed after Compose started) still refuses changed inputs until `effigy container down`. See [contract 005](../knowledge/contracts/005-container-runtime-contract.md). |
| Direct `compose_file` containers | `compose_file` is deprecated and read as project catalog fragments for one release, with a warning. Run `effigy container migrate <NAME>` to write `infra/dev/catalog/<container>-<service>/` and replace the key; the render does not change. Compose features a fragment cannot express refuse with the key to move. Named volumes become `<project>-<volume>`; old `<project>_<volume>` volumes are left alone. Published ports get Prepare-assigned host ports bound to `127.0.0.1` unless `[host].ports` fixes them or `publish_address` says otherwise. `effigy container eject` is retired; `effigy container render` shows the exact render. Translated containers carry checkout and scope labels, so the first `up` recreates them once. An existing unlabelled container created by v0.14.1 is adopted only with positive evidence: it passes full identity validation (Compose project, service, and runtime identity) and has a bind mount of this checkout at the policy working directory. Without that evidence, Effigy refuses rather than adopting. Labeled containers must match the checkout and scope identity; a matching `working_dir` alone is insufficient in a scoped checkout. If ownership cannot be proven, verify the stack belongs to this checkout, then run `effigy container down` followed by `effigy container up --detach` to recreate it. |
| The Queue/Nucleus host-run client (`--host-run-request-id`, `effigy tasks request status\|follow`, `HOST_RUN_TOKEN`, `EFFIGY_SCHEDULER_OVERRIDE`) | Removed (Q-006). Heavy selectors run directly unless the launcher sets `EFFIGY_ADMISSION_HOOK`; on a CI runner without a scheduler they now just run. Use `effigy --run-id <key> <task>` and `effigy run status\|logs\|stop <key>` instead of request ids; the old flag and command refuse with that replacement. Exit 75 now means only a held task lock; 77 is gone. See [guide 080](080-host-wide-validation-admission.md). |
| `qa`, `ci`, `ci:fresh` as heavy by name | No name implies a class. Declare `admission = "heavy"` on the tasks that should wait for a hook. |
| Linux workspace Effigy artifacts | An artifact is reused only when its identity matches the host binary and target. A stale one is rebuilt or downloaded, or the handoff refuses with the exact rebuild command. Release binaries download the matching Linux release asset. |
| `[containers.*.host_processes]` names | Names with surrounding whitespace, or two names that collide after upper-casing and replacing punctuation with `_`, are now rejected; they name dependency environment variables. |
| A container named `ports` | `effigy container ports …` is now the machine-wide port registry. A container with that name can no longer be addressed as `container ports <action>`; rename it. |
| Managed host listener routes | Without `EFFIGY_GATEWAY_PRIVATE_STATE_ROOT` they publish to the shared operator gateway. By default, a linked worktree or marked ephemeral clone gets a scoped apex (`api.acme-w<key>.test`), as container DNS routes already did. The primary checkout and checkouts with explicit `share_runtime_identity = true` retain the declared route name. |
| `effigy tasks status` and its JSON | Status is the run journal plus the task's gate: `effigy.tasks-status.v2` / `effigy.tasks-status-all.v2`. A long run reads `running` for as long as it lives; a run whose owner died reads `interrupted` with the settling command. Nothing is written or read under `.effigy/reports/tasks/` or `.effigy/runtime/tasks/` any more: old status history is dropped, not imported (it is history, not state), so a task with no kernel run rows reads `never-run`. See [contract 018](../knowledge/contracts/018-task-status-query-surface-and-read-model-contract.md). |
| Task locks and `effigy tasks unlock` | Every spelling of a task shares one lock, held exactly while its run lives and released when it exits, `kill -9` included. `effigy tasks unlock` is removed (it refuses with the explanation); remove any "run unlock when stuck" step. A lock conflict exits 75 and names the holder. Old `.effigy/locks/` files are ignored and can be deleted once no v0.14 run is live. |
| Flags after the task name | Effigy's flags go before the task: `effigy --lock-wait-ms 600000 build`, `effigy --plan build`. After the task name, `--plan` and `--json` still work for this release with a note; `--repo`, `--lock-wait-ms`, `--env-schema` and `--verbose-root` now reach the task, with a note. Check scripts and CI lines that pass them after the task. |
| Running from inside a member catalog | A subdirectory run resolves to the root that declares the catalog in `[catalog.members]`, however deep, instead of treating the nearest catalog as its own root. |
| Background processes started by a task | A plain host task's whole process group is stopped when the task ends. Start daemons with their own session (`setsid`, `docker compose up -d`), not `cmd &`. |
| `tasks.<name>.cache` and `effigy tasks cache` | Removed. A task that still declares `cache` is refused with the fix: delete the table. |
| `effigy container shell --bounded` | Discovery adds one small ownership listing to the preparation captures and budgets, and every effect targets the verified container. |
| Running v0.14.1 stacks | The first bring-up or stop imports each stack's lifecycle markers and labels into its environment record. Owned running stacks are adopted without a restart; the marker files under `~/.effigy/runtime/host-container-leases/` are read only and never changed. A stack whose ownership cannot be proven is not adopted; run `effigy container down`, then `effigy container up --detach`. See [contract 053](../knowledge/contracts/053-environment-reconciler-contract.md). |
| Stacks a task starts | They stop when the last run using them ends, not 5 minutes later. `effigy container up --detach` keeps a stack running; `EFFIGY_DISABLE_HOST_CONTAINER_LEASE=1` keeps task-started stacks running. Remove `EFFIGY_HOST_CONTAINER_LEASE_TIMEOUT_SECS` and `EFFIGY_DISABLE_HOST_CONTAINER_LEASE_REAPER`; they are ignored. |
| `effigy container down` (and handover, reset) while a task uses the stack | Refused, naming the holding run; nothing changes. Stop the run first (`effigy tasks status --all` lists it). A run's own cleanup is not refused. |
| Volume, data and reset commands | They target the backend the environment runs on, shown by `effigy container status` with the reason it was chosen. |

## New, opt-in

- `data_from` on `[containers.<env>]`: borrow another environment's service
  data volumes, so a container environment and its bundle-hybrid twin see one
  database and one bucket per checkout and switching between them hands the
  data over automatically. See [guide 063](063-container-system-guide.md).
- `effigy container ports status|reclaim`: port-registry capacity and safe
  reclamation. See [guide 063](063-container-system-guide.md).
- `effigy container <NAME> shell --command … --bounded`: deadline- and
  byte-bounded finite commands with the `effigy.container.bounded-exec.v1`
  payload.
- `EFFIGY_ADMISSION_HOOK`: gate `admission = "heavy"` tasks with your own
  command, held for the whole run. `effigy --run-id <key> <task>`,
  `effigy runs` and `effigy run status|logs|stop <run>`: name, inspect, follow
  and stop any run. See [guide 080](080-host-wide-validation-admission.md).
- Managed host listeners with readiness, routes and dependencies under
  `[containers.<name>.host_processes]`.
- `effigy gateway setup-tls|up --private-state-root <DIR>`: disposable,
  unprivileged gateway instances.

## DecodeLabs legacy sites

For a site using `decodelabs-effigy-bundle` (cbs, jal-accounts and similar):

1. Upgrade Effigy, then run `effigy container up --detach`. Adoption requires
   the identity and checkout ownership evidence described above. If that proof
   is unavailable, verify the stack belongs to this checkout, then run
   `effigy container down` followed by `effigy container up --detach`.
2. `effigy doctor` should report no errors. Earlier releases flagged
   `{ task = "defer …" }` references and `[isolation]`/`[state]` tables
   incorrectly.
